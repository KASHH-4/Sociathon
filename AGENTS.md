## Application structure

- Content routes render a shared TransitHear shell and view module so navigation and accessibility controls remain consistent.
- The compiled React SPA (`static/assets/*.js`) contains hardcoded/illustrative data. Do not edit the minified bundles.
- Python Flask backend (`app.py` / `run.py`) serves the SPA, PWA service worker, and all real API endpoints.

## Honesty labels and simulation policy

The following are **live and real** (not simulated):
- Browser Web Speech API transcription (Chrome/Edge/Android only) — audio is processed by the browser's speech service; no audio is ever stored by TransitHear.
- Rule-based announcement extraction and deterministic train resolution (local Python).
- Confidence fusion and reliability gate (local Python).

The following are **simulated** (`simulated: true` in all API responses):
- Official Indian Railways feed — all `official_updates` rows are created by the simulate endpoint; the real NTES API is not connected.
- ISL (Indian Sign Language) video — not yet integrated; placeholders only.
- Wearable connectivity — `/api/wearable/simulate-haptic` simulates a BLE device; no real wearable is connected.
- Facility verification states — seed data status values (verified_operational, conflicting, outdated, etc.) are illustrative.
- Gemini (when `GEMINI_API_KEY` is set) — real API calls, but responses are for illustrative transcripts only.

## Privacy rules (enforced in code)

- R7: Audio is **never** stored. `raw_transcript` column is always null.
- Non-announcement text (noise, conversation) is discarded after the rules gate; it is never persisted.
- The only identifier is a random `device_id` generated by the browser (`crypto.randomUUID()`).
- The Supabase service-role key is server-side only and is **never** sent to the browser.

## Seed data

All seed data (stations, trains, stops, facilities, alternatives) is illustrative. Train numbers and station codes are real Indian Railways references, but times, platforms, and facility states are invented for demo purposes.

## Adding new features

- Add blueprints in `transithear/routes/`.
- Keep existing routes (`/`, `/map`, `/communication`, `/recovery`, `/wearable`, `/api/health`, etc.) working.
- Never edit `static/assets/*.js` (compiled SPA bundles).
- Use `MemoryRepo` for development/tests when Supabase is not configured.
- Pipeline steps must never raise to the route handler.
